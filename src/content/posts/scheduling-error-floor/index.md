上一篇写的是一个想法在一天半里被证伪。这一篇的想法活得久一点——四天，三道嵌套的闸门，每一道都过了一半又挂在另一半上。

结论还是 KILL。但跟上次一样，最后得到的东西比原本那篇论文有用：一条能在写第一行代码之前就把这类想法筛掉的平方律。

## 一个正好空着的格子

背景是流式人体网格恢复（streaming HMR）。视频进来，每帧输出一个 SMPL 人体。当前的重模型每帧都要跑一次，很贵。

已有的加速工作分两支。一支做模型内部压缩：token 合并、层合并、pipeline 重构，都是在"跑一次要多久"上做文章。另一支做抽帧：DeciWatch 那一路，均匀采样不到 10% 的帧，然后用一个双向 transformer 把中间补回来，效果很好。

第二支有个共同前提：**非因果**。它们要看到未来帧才能恢复中间。这在离线处理里没问题，在流式场景里直接出局。

而 OnlineHMR 那一路守住了因果性，代价是每帧都跑重模型。

所以格子是这样的：因果 + 预算受限 + 由预测失效驱动的在线调度——空的。

我的想法就落在这儿：一个轻量运动模型在线维护 belief state，逐帧预测下一帧；只有当预测开始失效时才调用昂贵的重模型。判据是**动力学 innovation**，不是外观差异。这一条很重要——帧差和光流会在相机平移时疯狂触发（人其实在匀速走），又会在人突然绊一下时毫无反应（画面几乎没变）。

失效点清楚、护城河清楚（因果性）、大部分网络冻结、四页纸的形状齐了。

## 三道嵌套的闸门

跟上次一样，先写死判决标准再动手。这次分三层，每层都便宜到能在一天内出结果。

**Phase 0**：完全不碰图像、不碰任何模型。只用 3DPW 的 GT 关节位置，假设"感知 = 拿到真值"，问一个纯运动学问题——人体运动有没有足够的突发性，让非均匀调度显著优于均匀调度？用动态规划求预算约束下的最优调度作为 oracle 上界。GATE-0：B=25% 时 oracle 相对 uniform 的 MPJPE 降幅 ≥ 15%。

**Phase 0.5**：加观测噪声。perceive 帧拿到的不再是真值，而是带噪观测。扫 σ，看 gap 衰减到哪儿。

**Phase 0.6**：真跑重模型，测真实残差结构。

这个顺序的意义是：**每一层的成本都比下一层低一个数量级，而每一层都能独立杀死项目**。Phase 0 只要几小时，不用装任何依赖——顺带说一句，我这台机器当时连 conda 都没有，系统 python 是 2.7，读 SMPL 模型需要的 chumpy 也没装。Phase 0 一个都不需要，这本身就是设计的一部分。

## 第一天：36%

Phase 0 跑完，四条判据全过，而且过得很凶。

B=25% 时，uniform 10.205mm，oracle 6.514mm，**gap 36.17%**。B=12.5% 时 39.72%，满足"预算越紧调度越重要"。逐 track 的 gap 中位数 30.16%，不是被两三条剧烈运动的序列撑起来的。

突发性诊断也给了一个当时看着很好的信号：预测误差的时间自相关，lag-1 0.929，lag-30 还有 0.443。突发成簇——这意味着一个因果 gate 有希望学到它。抓不住的是不可预测的尖峰，抓得住的是缓变的 regime，而数据说是后者。

DP 用小规模 brute-force 对照过，预算、首帧、最大间隔约束都验过。37 条 person track，592 个调度文件。

看起来非常好。

## 现实化的滑梯，和我猜错六倍的那个参数

然后开始往里加现实性。每加一层，gap 掉一截。

| 现实化步骤 | gap(B=25%) |
|---|---|
| Phase 0 原始 | 36.17% |
| uniform 允许选最优相位 | 28.27% |
| 换成更强的传播器 AR(3) | 22.38% |
| 加 σ=10mm 观测噪声 | 6.64% |

第一步是我自己给自己加的。原来的 uniform 是固定相位的，B=12.5%（stride 8）时，相位选得好不好本身就能贡献可观的差距。允许 uniform 在 K 个相位里取最优——**这一步就吃掉了 8 个点**。所谓 36%，有接近四分之一是运气。

第二步补的是一个漏洞。Phase 0 里我设计了一条"更强传播器"的复核臂，用 root 常加速度替代常速度。跑完发现两条臂的数字**逐位相同**——root 的常加速度在 root-relative MPJPE 下被完全消去了。那条臂根本没执行。换成真正不同的 AR(3)（在 train split 上拟合），gap 22.38%。

第三步是我犯的最大的错。

我拍了一个 σ=10mm 的观测噪声，理由是"HMR 帧间抖动大概 10–20mm"。这个数字是估的，从没测过。而整个判据 2 就挂在它上面——实测显示答案在 σ=2（15.42%，压线过）和 σ=5（11.13%，不过）之间翻转。

后来用公开的 Accel Error 反解，得到 σ ≈ 0.9–1.7mm。**我高了 6 到 10 倍。**

于是我平反了一次：判据 2 是假阴性，是我一个错误的参数把它打挂的。这一条要写进修订记录——"判据锚定的参数经实测证明设错了"和"看到数字之后放宽阈值"是两件完全不同的事，必须白纸黑字分开，否则过两天自己都说不清。

但平反救不了真正的问题。因为无论 σ 怎么定，**可调度收益的绝对值一直在 2–3.7mm 之间**，而 HMR 自身的误差是 40–70mm。σ 的修正把相对 gap 从 6.64% 拉回 15%，可分子没变——变小的是分母（传播误差本身），而论文里的分母是感知误差底噪。

最后一道冻结判据是这样定的：在 σ ≤ 2mm 下，存在某个预算档，同时满足（a）绝对差距 ≥ 5mm；（b）恢复的退化比例 ≥ 30%；（c）oracle 污染 < 5pp。

结果：（a）和（c）在 B=12.5% 和 6.25% 都过了，最好的一格绝对差距 14.6mm。（b）最高 26.8%，差 3.2 个点。

而且在 σ=0 时全速率误差恒为零，（b）严格等于 gap 本身，最好的一格是 25.42%——没有任何解释空间。

## 两条备选故事，同一种死法

一个想法死之前通常还有两条命。

**第一条命是换指标。** 均匀抽帧加传播容易产生"平滑但错误"的轨迹，而调度把 perceive 放在动力学转折点上，理应在加速度结构上占大便宜。所以 Accel Error 是天然的备选主指标。我当时估的是：如果 Accel gap 有 25–40%，故事重心就整体搬过去。

实测 **4.77%**。P5 Kalman 那一行甚至是 **−0.62%**。

这不只是备选路径没走通，是我对这个系统的定性模型错了。合理的解释是：滤波传播器本身已经把轨迹磨平，Accel Error 主要由噪声和平滑特性决定，跟 perceive 放在哪儿关系不大。

**第二条命是换主张。** 数据里最强的信号根本不在调度上：σ=10 时 Kalman belief state 相对带噪一阶差分改善 48.65%，绝对 33mm，是调度收益的 15 倍。

如果这堆数据里有论文，它在**估计器**上，不在 gate 上。对应的主张也强得多：不是"比 uniform 调度好"，而是"**25% 算力，精度打平甚至超过全速率**"。这就是 DeciWatch 的因果版，因果性是真护城河。

但这条路成不成立，取决于一个从没测过的量：**HMR 误差里有多少是可以被时序滤波去掉的白噪声。** 滤波只能去掉白的，去不掉相关的。

于是有了 Phase 0.6。

## 最后一次复活，和它的死法

跑 Multi-HMR，5 条序列 6700 帧 10 条 track，匹配覆盖率 99.56%。用 lag-0 与 lag-1 自协方差的落差估白噪声分量：

$$\hat\sigma_\text{jitter} = \sqrt{3(\gamma_0 - \gamma_1)}$$

结果 18.297mm，冻结的复活线是 15mm。**REVIVE。**

我没敢直接用。因为那个统计量按定义等于 $\sqrt{3\gamma_0(1-\rho_1)}$，它只是"残差幅度 × 一步去相关"的重新表述。它等于白噪声方差，当且仅当相关分量在 lag-1 上完全光滑——而这个假设一步都没被检验。

per-track 表里有个反常直接指向假设不成立：

- `downtown_bar_p00`：MPJPE 96.14mm（全场最大），ACF 0.978，估出的 jitter 14.13mm（偏小）
- `downtown_bus_p00`：MPJPE 74.06mm，ACF 0.881，jitter 26.42mm（全场最大）

**误差最大的 track 反而 jitter 最小。** 如果 jitter 是模型的逐帧噪声属性，它该随误差幅度走，不该反着走。更自然的解释是：bus 场景运动快、相机晃，相关误差分量去相关快，jitter 被高估。

三个检查，全部在缓存数据上跑，一小时：

1. **nugget test**：用 lag-2..10 的自相关外推回 lag-1。真有白噪声，lag-1 会掉在外推曲线下方；没有，就落在曲线上。结果：均值 5.499mm，**中位数 0，10 条里 6 条为零**。
2. **归因**：jitter 与人体运动速度相关性 Pearson 0.032，与**相机角速度** Pearson 0.560。GT 是被逐帧相机位姿旋转进模型坐标系的，关节到 pelvis 的力臂约 400mm，2° 的旋转抖动就是 14mm——几乎是整个预算。
3. **直接反解**：Multi-HMR 的 Accel Error 实测 15.118 mm/frame²，按同一套公式反解得 2.85mm/轴，不是 10.6mm。

18.297mm 是测量伪影。

然后是那个应该一开始就做的实验——**别再推断了，直接测那个主张本身**：对全速率 Multi-HMR 轨迹跑一个因果滤波器，看 MPJPE 掉多少。冻结门槛 ≥3.5mm 且 ≥5%。

结果：70.559mm → 70.452mm。**收益 0.107mm，0.152%。** 最好的 EMA 变体也只有 0.269mm。

同一个滤波器把 Accel Error 从 15.118 砍到 7.841 mm/frame²，**砍掉一半**。

更平滑，但不更准。地板是硬的。

## 真正的答案是一个平方

事后回过头推，这件事在写第一行代码之前就能算出来。

设感知误差底噪 $E_\text{perc}$（重模型自身的误差），预算 $B$ 下的传播误差 $E_\text{prop}(B)$。两者近似独立时，加速系统的总误差

$$E_\text{total} \approx \sqrt{E_\text{perc}^2 + E_\text{prop}^2}$$

调度器做的事，是把 $E_\text{prop}$ 从 uniform 降到 oracle。定义**可调度系数**

$$\alpha = \frac{E_\text{prop}^{\text{uni}} - E_\text{prop}^{\text{ora}}}{E_\text{prop}^{\text{uni}}}$$

实测在可用预算档上 $\alpha \approx 0.18$–$0.28$。

记 $r = E_\text{prop}/E_\text{perc}$。当 $r \ll 1$，把两个根号展开到二阶：

$$G = \frac{\sqrt{E_\text{perc}^2+E_\text{prop}^2}-\sqrt{E_\text{perc}^2+(1-\alpha)^2E_\text{prop}^2}}{\sqrt{E_\text{perc}^2+E_\text{prop}^2}} \approx \frac{\alpha(2-\alpha)}{2}\,r^2$$

代进 HMR 的数：B=25% 时 $E_\text{prop} \approx 15.4$mm，$E_\text{perc} \approx 55$mm，$r = 0.28$，$\alpha = 0.22$，得 $G \approx 1.6\%$。我实际做的稀释估计是 2.0–2.9%，量级对得上。

**关键在于 $r$ 是平方进来的。** 比值差 3.6 倍，收益差 13 倍。而我这个任务上比值是 0.28——方向还反着。

再加一个约束就更彻底了。加速系统要可用，精度退化不能太离谱，就算宽松到允许 10%：

$$\sqrt{E_\text{perc}^2+E_\text{prop}^2} \le 1.1\,E_\text{perc} \quad\Longrightarrow\quad r \le 0.46$$

代回去：

$$G_\text{max} \approx 0.22 \times 0.46^2 \approx 4.6\%$$

这是 **oracle** 的天花板。真实 gate 大概能回收 oracle gap 的 40%，也就是 2% 出头。

换句话说：**只要你要求加速系统的精度退化不超过 10%，那么调度类方法在任何任务上的可见收益上限就在 5% 左右，而且这个上限跟你的 gate 有多聪明无关。**

这解释了我遇到的那个挤压。gap 确实随预算收紧而增长——B=6.25% 时 gap 到 25%，绝对差距 14.6mm，好看得多。但那一档 uniform 光传播误差就 58.8mm，叠上 55mm 的感知底噪，系统输出 80mm 以上，比十年前的方法还差。**调度只在系统已经不可用的预算档上才变得显著。**

所以筛选规则是两个数，都能在一天内测出来：

1. **$r = E_\text{prop}(B)/E_\text{perc}$ 在可用预算档上的值。** 要 $r$ 接近甚至超过 1，调度才值得做。这要求感知本身足够准——相对于被跟踪对象的运动而言。HMR 差了 4 倍。
2. **$E_\text{perc}$ 里的白噪声占比。** 如果它很大，时序滤波能把地板本身降下来，游戏规则就变了。DeciWatch 那条非因果路线吃的就是这口饭，而且双向 transformer 是比因果滤波强得多的去噪器。我实测 Multi-HMR 在 3DPW 上残差几乎全是时间相关的，白的部分买不回 0.11mm。

第一个数决定调度值不值得做，第二个数决定滤波值不值得做。**两个都是先测再写代码，不是写完代码再测。**

## 一个反直觉的推论：world model 越好，调度越没用

顺着 $\alpha$ 往下想，会得到一个当时让我愣了一下的结论。

看 σ=0、B=25% 的实测：

- P0 常速外推：uniform 10.205mm，绝对差距 2.88mm
- P4 AR(3)（明显更强）：uniform 8.372mm，绝对差距 **1.87mm**

传播器越强，uniform 误差越低，**可调度的绝对收益也越小**。机制很清楚：好的运动模型本来就能扛过更多帧，调度的可操作空间被压缩了。

这一条推翻了我心里最后一个反驳——"我们还没训真正的 world model，所以不算数"。我原计划在 AMASS 上训一个 5M 参数的 GRU 当传播器。它只会比 AR(3) 更强，所以它会让判据更难过，不是更容易。

**"我们还没做真正的系统"在这里不是救命稻草，是加速器。**

更一般地说：调度类方法和预测类方法在同一块蛋糕上抢食。你把预测做好，就是在削自己调度的空间；反过来也一样。一篇同时主打"更好的 world model"和"更聪明的调度"的论文，两个贡献在数学上互相拆台。

## 副产品：你的 oracle 可能在偷看答案

这一条跟 HMR 无关，但我觉得它是这四天里最通用的收获。

Phase 0.5 里我用 DP 求带噪观测下的最优调度。写 spec 的时候留了一手：**每个配置抽两份独立的噪声实现**，一份用来建代价矩阵、求 DP 调度，另一份用来给所有调度器评分。

理由是：带噪之后，oracle 会去挑"噪声恰好小"的帧。它不是在找运动上该 perceive 的时刻，是在找观测碰巧准的时刻。而那种信息真实系统永远拿不到。

我同时把污染版（solve = eval）也报了出来，因为两者之差本身就是个有价值的数字。

结果：**11.67 ± 0.23 个百分点**（R=20 复核，不是偶然波动）。

也就是说，如果我没做这个分离，我会拿到一个虚高 11.67pp 的 oracle 上界，然后所有"回收了 oracle gap 的百分之多少"的判据都会以它为分母，全线失真。

这条判据当时把整轮结果判成了 INVALID——防护起作用了，代价是结论作废、要重新解读。但我认为这个代价花得很值：**任何在带噪数据上求 oracle 上界的论文都可能中这一招，而做 solve/eval 分离的几乎没有。**

顺带一个小规矩，同一轮里学到的：**每个相对 gap 旁边必须有绝对值。** 我有一条传播器的 gap 在 σ=20 时还有 31.87%，看着像好消息，实际是它的绝对误差已经爆到 251mm，oracle 只是靠把间隔压到 1–2 帧来避免发散。这次是差点被误导向乐观，下次可能是反向。

## 为什么这四天没白花

**嵌套闸门比单个闸门值钱。** 三层，每层成本差一个数量级，每层都能独立杀死项目。Phase 0 那几个小时不需要装任何依赖、不需要跑任何模型——如果它当天挂了，我的总成本就是半天。它没挂，我才有理由去付 Phase 0.5 的成本。真正的重模型推理一直拖到 Phase 0.6 才跑，那时候项目已经被筛过两轮了。

**顺序错了。** 我的流程是：想法 → 可行性验证 → 发现效应太小。应该是：想法 → **量级估算** → 可行性验证。上面那个平方律二十分钟就能算完，而且需要的两个输入（传播误差、感知底噪）都是公开数字或者一天内可测。我是在第四天才把它推出来的。

**测量比推断便宜。** 整个 Phase 0.6 的争论——白噪声占多少、坐标系有没有引入伪影、单位换算对不对——都是在**间接推断**"滤波能不能降低误差"。而这件事可以直接测：拿全速率预测跑一遍因果滤波，看 MPJPE 掉多少。30 分钟，一步跳过所有假设。我绕了一天才想到该这么做。

**我在数值上错了两次，在结构上一次没错。** σ 猜错 6 倍，Accel 预测错 5 倍。但"效应量 vs 底噪"那个结构性论证从第一天到最后一天没被推翻过——它只依赖 2.7 和 55 两个实测数的算术。这也是一条关于自己的校准信息：量级论证可以多信，具体数值预测少信。

---

题外话：这四天里我最喜欢的一个瞬间，是看到那个滤波器把 Accel Error 砍掉一半、MPJPE 纹丝不动的时候。

Accel Error 是这个领域里到处都在报的指标，通常被当成"时序质量"的证据。而我这个实验说明：它可以被一个十行的因果 Kalman 免费砍半，同时精度一点没变好。**它跟准确性近乎解耦。**

我不知道这算不算一个已知的事实——大概是的，滤波器降平滑度指标本来就是它的定义。但当你看到一个被广泛引用的指标在你自己的数据上被这么轻易地推动，而它旁边那个真正重要的数字一动不动，那种感觉还是很具体的。

以后再读到主打 Accel 提升的论文，我会先去找 MPJPE 那一列。
