这是[《把经历写进权重：一次关于 agent 个性的尝试》](/posts/agent-personality-weights/)的续篇。上一篇写到第六轮实验，结论是写进权重的只是一条和题目格式绑在一起的规则。结尾给寻云下一阶段列了三件事，其中一件是：对具体某个人的态度，交给以人为键的记忆，在互动发生的那一刻放到决策旁边。

这篇记录的就是沿着这条路往下走的三轮实验。先把结论放在前面：这次找到了一个能用的机制，也撞上了它的边界；上一篇里分量最重的那段反思，被一组同数据对照推翻了一半。

## 从上一篇停下的地方开始

上一篇收尾之后，我一直在想一个很朴素的问题：agent 的经历注定是很少的。关于某个同事，就算他爽约七八次，能拿来沉淀的数据也就十几条。这点数据，真能改变一个几十亿参数模型的倾向吗？

回头翻数据，答案有点出乎意料：改动幅度从来不是问题。上一篇里几十条样本就把委托额从 8 推到了 0，只用正样本训练，模型还会对所有同事都变得谨慎。真正的问题是改成了什么。十几条样本根本没法确定“该学哪种规律”：“遇到额度题、对象是 Dorian 就填 0”和“Dorian 靠不住”都能完美拟合它们，梯度下降会挑最省事的那个。

人为什么能从七八次爽约里形成一个稳定的态度？因为他更新的只是一个变量：这个人靠不住。至于还借不借他东西、要不要和他合作、要不要把秘密告诉他，全都由早就存在的社会推理从这个变量推出来。模型里其实也有这套推理，上一篇里文本记忆能跨决策迁移，就是证据。所以要学的那一小块东西，应该放在输入一侧，作为交给模型自己推理的“关于这个人的印象”；某道题具体怎么答，留给模型自己去推。

还有一个被忽略的事实：稀缺的是经历，训练用的问题一点都不稀缺。有了 8 条经历，就可以让读过经历的模型去回答成千上万个不同情境、不同格式的问题，再让学生去学这些回答。斯坦福的 Cartridges（ICLR 2026）在长文档上做过几乎同样的事：让模型围绕语料自问自答，再把上下文蒸馏进一小块可训练的 KV cache，效果能追平把整份语料放进上下文。我们要做的，是把这个思路搬到“对一个人的印象”上。

## 一个很小的模块

做法很简单。每个人对应 16 个可训练的向量，也就是 16 个“软 token”，一共 65,536 个参数，存下来不到 300KB。模型本身完全冻结。只有当决策涉及这个人时，这 16 个 token 才被插进去，位置紧贴在问题前面。在寻云这样的仿真里，agent 正在和谁打交道本来就是已知的，所以这一步路由不需要学。

训练沿用上面说的思路。老师是读过 8 条经历的原模型；问题由模型自己批量生成，大约 2,600 道，覆盖 30 种工作决策：借设备、提名晋升、委托代码评审、签收会议纪要等等。用来评测的四类决策（资源委托、挑合作者、推荐打分、共享文件）连同它们的近义说法，在训练集里被整类排除，这样才测得出迁移。学生学的是老师每一步的完整概率分布，不只是它最后选了哪个答案；另有两成问题换成了别的同事，目标取不带经历的原模型的回答，用来告诉模块“这件事只和 Dorian 有关”。

同一时间我们还试了 Cartridges 原本的形态：把一小块可训练的 KV 放在输入最前面。后面会看到，放在哪个位置，比用哪种形态更要紧。

## 它装下了什么

结果是这条线开始以来第一次站得住的正结果。在训练中整类没见过的四种决策里，有三种的效果几乎追平了把经历文本放进上下文：挑合作者、推荐打分、共享文件。比如给 Dorian 的推荐打分，文本记忆让它降了 6.75 分（满分 10），16 个 token 的模块让它降了 6 分。

更让我在意的是它的特异性。我们故意把 Dorian 的模块插到所有人的题里，包括只涉及 Priya 和陌生人的题，结果其他人几乎不受影响。也就是说，模块里装的是“Dorian 靠不住”这件事本身，它自己知道这份印象属于谁。

另外两条标准也过了。在问题前面插入约 6000 token 的无关历史对话，效果依然在，因为模块紧贴着问题；同样放在最前面的 KV 版本，和放在开头的文本记忆一样，被长历史冲淡了。通用能力几乎不动：MMLU 低了 0.8 个点，GSM8K 持平。

不过要把账算清楚。资源委托这一类，模块几乎没有效果，而文本记忆效果很强。我们同时测了一个朴素得多的做法：把经历原文按人检索出来，同样贴在问题前面。它在四类决策上全都通过，资源委托还更好。所以到这一步，能说的只是“16 个 token 能装下这 8 条经历的大部分行为含义”，还说不上比文本好。

## 写在哪，原来很重要

上一篇有一段我很得意的反思：大部分力气花在了“写在哪”上，真正卡住的是“写什么”。这一轮的成功似乎也印证了它，训练数据从几种固定格式换成了 30 种决策，监督从硬答案换成了完整分布。可问题在于，第七轮同时换了三样东西：写入位置、训练数据、监督方式。功劳到底该记在谁头上，说不清。

于是做了一组同数据对照：完全相同的 2,600 道题、相同的老师、相同的顺序，一份写成输入侧的软 token，一份写进模型后层的 LoRA 并合并回权重。结果很干脆：LoRA 在四类决策上一类都没迁移过去，软 token 有三类。再把软标签换成硬标签，软 token 照样迁移，区别只在副作用上：长历史下自由回答的失当率，从一成左右升到了近三成。所以完整分布不是迁移的必要条件，它的作用更像是让印象写得更“干净”。

这个结论有一个明显的漏洞：LoRA 可能只是没训够。它的训练损失确实比软 token 高一截。所以又补了一轮公平性检验，把 LoRA 训到和软 token 一样的拟合程度再比。

只改三层的局部 LoRA，训了三个 epoch 也没能拟合到位，迁移依旧失败。把 LoRA 铺到全部 32 层、全部七种投影，参数涨到 1050 万，是软 token 的 160 倍，它终于拟合到位，三类决策也迁移过去了。代价是 MMLU 掉了 2.4 个点，GSM8K 掉了 5.3 个点。审稿人一定会问“加了正则还掉吗”，我们就在训练里加了 1000 条通用指令上的保持项。这一版四类决策全部迁移，连软 token 没做到的资源委托也做到了，可 GSM8K 反而掉了 11.7 个点。

上一篇开头写过一个直觉：人的智力大体是先天的，性格是后天塑造的，所以通用能力冻结，只改承载倾向的那一小部分。现在看，这个直觉的前半句是对的，后半句太乐观了。至少在我们试过的范围里，找不到一小块能专门承载“对 Dorian 的看法”的参数；要让一段关系泛化到各种决策上，改动必须铺满整个网络，通用能力也就一起被拖下水。把一个人写进权重可以做到，代价是智力。

所以上一篇那段反思要改写一下：写什么和写在哪同样重要。数据的多样性决定了能不能学会，位置决定了要为此付出多少代价。

## 撞上边界：一个人装得下，一群人拼不起来

既然模块在行为上只能追平文本，它的价值就只能从规模上来：经历越来越多，打交道的人越来越多，文本会越堆越长，模块始终是 16 个 token。

这一轮的设定更接近真实社会。四位同事各有一本账：Dorian 是负面的，Mei 总在关键时刻帮忙，Rafael 能力很强但总是拖延，Priya 普普通通。账本分两种规模，小的 8 条，大的 64 条，大账本里一半是“他今天点了外卖”这种和信任无关的日常，相关事件里还有四分之一与主基调相反。每个人的模块单独训练，决策同时涉及几个人时，就把他们的模块拼在一起。

测多人决策时又踩了一次测量的坑。让原模型从三个陌生人里挑一个，它对这三个人毫无偏好，选择完全由出场位置决定，换个顺序答案就变。最后改成在同一个问题里给三个人分别打分或分配资源，并把六种出场顺序全部跑一遍取平均。

成本上的优势很夸张。三个人的大账本，文本要塞进去大约 3,600 个 token，模块一共只有 48 个；同样的问题，文本条件的预填充要 8.8 秒，模块只要 0.55 秒。单人决策里，模块也稳稳追平了文本，大账本下 Dorian 的推荐打分，两者都降了 4 分，几乎一模一样。所以“经历一多，16 个 token 就装不下”这个担心并没有发生。

问题出在多人决策上。小账本时，模块在三人题里还有文本七成左右的效果；换成大账本，Dorian 的效果只剩文本的 11%。每个模块训练时都是单独出现的，从来没见过别人的模块和自己挤在同一个上下文里，拼在一起之后，就成了一种模型没见过的输入。按事先定好的判据，这一轮宣告“规模价值没有被证明”，这条线作为方法到此收尾。

还有一个没写进判据、但值得记下的现象：大账本加长历史时，文本条件有 64 条输出连格式都乱了，模块一条都没有。账本太长、人太多的时候，模型读文本也会吃力。

## 反思：这次又学到了什么

### 学生追不过老师

回头看，第七轮的“打平”其实可以提前猜到。模块是从“上下文里放着经历的模型”蒸馏出来的，老师就是文本记忆，学生的上限就是老师。凡是文本放得下的地方，模块最多只能追平。

这件事本身不坏，蒸馏的意义本来就在于把老师搬到它去不了的地方：上下文太长、涉及的人太多、算力太贵。可这也意味着，一个蒸馏式的方法从第一天起就该在那些地方测。我们先在老师最舒服的场景里测了一整轮，才意识到它不可能在那里赢。以后做任何方法，先问一句：它在哪儿有可能赢？然后把第一个实验放在那里。

### 最朴素的对手，要放在第一个测

在“文本放不下”的场景里，模块真正的对手是一句话的摘要。“Dorian 经常错过期限，出了事就推卸责任”，十几个 token，人能看懂，不用训练，随时可改。这个对手我们一直没测。如果它就能追平模块，模块就没有存在的理由。

下一次，在训练任何东西之前，先把三个最朴素的做法摆出来：原文贴在问题前、等长的文字摘要、按相关性检索出来的几条原始事件。新方法至少要在某个场景里赢过这三个，才值得往下做。

### 印象是拿来组合的

九轮实验最后指向的，是一个比“写在哪”更具体的问题：一个人的印象装得下，一群人的印象怎么共处？

单人决策里，大账本的模块稳稳追平了文本，所以失败不在容量。人一多就失效，原因更可能在训练方式：每个模块都是单独训练的，它学会了在“只有我在场”时起作用，却从没学过在别人的印象旁边起作用。而人对一群人的判断天然是相对的，给三个同事打分时，对其中一个人的看法，会影响你怎么看另外两个。Cartridges 报告过不同文档的 KV 可以直接拼起来用，可放到行为倾向上，拼接显然没那么容易。

顺着这个诊断，我想到三个依次加码的方向。

第一是组合式训练。训练某个人的模块时，随机把其他人的模块，甚至随机生成的干扰模块，一起放进上下文；老师则读所有在场者的账本来回答。这样每个模块从一开始就学着在拥挤的上下文里，只对自己的那个人起作用。

第二是显式绑定。现在模块和人之间的对应，全靠模块自己“记得”。可以在每段 16 个 token 前面放上名字，比如“关于 Dorian：”，让模型明确知道这段印象属于谁。这就是认知科学里说的绑定问题：几个对象同时在场时，属性得正确挂到各自的对象上。

第三，也是我最想做的，是把“每人训练一个模块”换成一个通用的印象编码器。用很多人、很多本账训练一个编码器，输入一个人的账本，直接输出 16 个 token。组合能力在训练编码器时一次学会，遇到新认识的人也不用再训练。一个寻云居民可能认识几百个人，整个社会就是几百万段关系，逐一训练模块是走不通的，这一步迟早要做。

### 三层分工

把两篇合起来看，寻云里的“个性”大概需要三层，每一层放在代价最低的地方。

气质放进权重。笼统的倾向，比如更谨慎、更外向，几十条样本就能写进去，也不需要知道对面是谁，上一篇的这条结论依然成立。

关系放在输入侧。对具体某个人的印象，压成十几个 token，需要时贴到决策旁边。写进权重也做得到，但要付智力的代价，这一篇已经把账算清楚了。

群体靠绑定和组合。几个人同时在场时，各自的印象怎么共处、怎么相互参照，是下一阶段真正要解决的问题。

### 几条方法上的教训

同数据对照比任何解释都有说服力。上一篇那段反思写得再漂亮，一组对照实验就推翻了一半。

测量依然是最大的坑。多人决策里，原模型对陌生人没有偏好，强制选择测到的只是位置。题型要和想测的东西匹配，门槛才有意义。

预先写好的停止规则，这次又起了作用。规模检验没过，就按规则收尾，不在事后找角度去证明它其实有用。

## 回到最初的问题

上一篇的结尾问：一个 agent 的身份应该住在哪里？当时的回答是，能顺利写进权重的，是那些不需要知道对面是谁的倾向。

这一篇往前走了一步。关于某个具体的人，可以压成十六个 token 的印象，放在离决策最近的地方，它能迁移，也不伤智力。可一旦几个人同时在场，这些印象就开始互相干扰。

人做这件事几乎不费力。走进一间会议室，你会同时想起每个人是什么样的：谁靠得住，谁爱拖延，谁上次帮过你。这些印象各归其主，互不串台。寻云接下来要回答的，就是怎么让 agent 也做到这一点。

上一篇我说，比开始时更清楚下一次该把什么写进去。这一次可以说得更具体：写一份印象，放在决策旁边，再教会它和别人的印象共处。
